# module/ — код системы Order

> Гайд для разработчика (как проходит атака, сокет, криты, эффекты, отладка, чек-лист проверки): [`docs/DEVELOPER-GUIDE.md`](../docs/DEVELOPER-GUIDE.md).

Точка входа — `Order.js` в корне системы. Он импортирует всё отсюда и раскладывает регистрацию по хукам `init` и `ready`. Отдельными esmodules в `system.json` подключены ещё четыре самостоятельных файла: настройки клиента, рейтинг игроков, Token HUD и скрытность токенов.

## Директории

| Папка | Что внутри |
|---|---|
| `core/` | Общие кирпичики без UI. `socket.js` — транспорт «игрок → GM», `dice.js` — d20, криты, исход защиты, `effects.js` — чтение Active Effects в формате v14, `side-effects.js` — какой клиент записывает побочные изменения из `prepareData()`. |
| `documents/` | Классы документов: `OrderActor`, `OrderItem`, `OrderCombat`. |
| `combat/` | Атаки оружием: ближний бой (`OrderMelee`), дальний (`OrderRange`), формула атаки, АоЕ-шаблоны, запомненный уворот, баффы брони и оружия. |
| `spells/` | Заклинания: каст (`OrderSpell`), потоки доставки (атака, область, спасброски, объекты и зоны, призыв), защитные заклинания, эффекты. |
| `skills/` | Навыки: то же, что у заклинаний, плюс кулдауны. |
| `items/` | Расходники (`OrderConsumable`) и реестр тегов способностей. |
| `mechanics/` | Правила, общие для нескольких потоков: формулы урона, цепочка доставки, спасброски, скрытые характеристики и броски, подписи бросков, Испытание духа, скрытность, магическая усталость сверх предела (`OrderMagicFatigue`). |
| `sheets/` | Листы. `*X.js` — новые листы (JRPG), по умолчанию для игроков и основных предметов. Остальные — классические, остаются в выборе листа. |
| `apps/` | Отдельные окна: мастер создания персонажа, повышение ранга, массовый бросок, выбор целей, менеджер тегов, гайд по листу. |
| `ui/` | Скин окон и чата (`OrderUiSkin`), звуки, хотбар, настройки клиента, рейтинг; `token-hud/` — Token HUD. |
| `migrations/` | Миграции данных мира. Запускаются в `ready`, только у GM, один раз на версию. |
| `debuffs.json` | Справочник дебаффов и их ступеней. Грузится через `fetch("systems/Order/module/debuffs.json")`. |

У каждого файла в начале есть комментарий: что он делает и с чем связан.

## Запросы к GM (шины)

Игрок не может менять чужие документы: токен врага, карточку атаки, эффекты цели. Поэтому такие действия выполняет GM.

1. Модуль механики регистрирует обработчик своей шины: `registerGMHandler("meleeBus", fn)`. Обработчики подключаются в `ready` в `Order.js`.
2. Клиент игрока шлёт `sendToGM("meleeBus", { type: "RESOLVE_…", … })`.
3. Запрос уходит по веб-сокету `system.Order` одному активному GM. GM подтверждает получение и вызывает обработчики шины. Каждый модуль смотрит на `payload.type` и пропускает чужие типы.
4. Если подтверждение не пришло за 4 секунды, запрос дублируется скрытым сообщением в чат (старый путь). Так бывает, например, когда сервер не перезапускали после правки `system.json`. Повторное выполнение исключено по `requestId`.

Шины: `meleeBus`, `rangedBus`, `spellBus`, `skillBus`, `consumableBus`. Подробности — в комментарии в начале `core/socket.js`.

Важно: веб-сокет системы включается строкой `"socket": true` в `system.json`. Сервер Foundry читает её только при запуске, поэтому после обновления системы сервер нужно **перезапустить**. До перезапуска всё работает через запасной чат-путь.

## Соглашения

- **Броски d20.** Чистые 1 и 20 определяются только через `core/dice.js` (`isNaturalOne` / `isNaturalTwenty`): они учитывают kh/kl при преимуществе и помехе. Исход «атака против защиты» считает `resolveDefenseHit`: атака больше защиты — попадание, ничья — защита успешна. Чистая 1 (крит. провал) исход не меняет, она только отображается: метка `critFailTagHtml()`, абзац `critFailDefenseHtml()`, ячейка АоЕ `critFailAoECell()`.
- **Запись из `prepareData()`.** Перед любой записью в базу проверяйте `shouldPersistActorSideEffects(actor)` из `core/side-effects.js`, иначе запишет каждый подключённый клиент.
- **Active Effects (v14).** Изменения эффекта читаются только через `getEffectChanges(effect)`. Тип изменения пишется строкой: `type: CHANGE_TYPES.ADD`. Не читайте `change.mode` и не используйте `CONST.ACTIVE_EFFECT_MODES`: в v14 это пишет предупреждения в консоль.
- **Удаление ключей.** Используйте `{ "flags.Order.x": _del }` вместо старого `"flags.Order.-=x": null`.
- **Чат.** Хук `renderChatMessageHTML` получает `HTMLElement`; `renderChatMessage` устарел.
- **Окна.** Диалоги пока на AppV1 `Dialog` (`foundry.appv1.api.Dialog`). Он работает в v14, но будет удалён в v16.
